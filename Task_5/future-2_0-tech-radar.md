# Технологический радар «Будущее 2.0»

## Легенда
- **Adopt** — активно используем, рекомендовано для всех новых проектов
- **Trial** — пилотируем, ищем подтверждение ценности
- **Assess** — оцениваем, изучаем, пока не используем
- **Hold** — не используем, есть ограничения или лучшие альтернативы

---

## Архитектурные паттерны

| Паттерн | Статус | Назначение | Обоснование статуса                                                           |
|:---|:---|:---|:------------------------------------------------------------------------------|
| **Data Mesh** | Adopt | Децентрализованное владение данными по доменам | Ключевой паттерн трансформации. Без него целевая архитектура невозможна.      |
| **Event-Driven Architecture** | Adopt | Асинхронная коммуникация через события | Основа всех интеграций, заменяет синхронные вызовы ESB.                       |
| **Self-service BI** | Adopt | Портал для самостоятельного построения отчётов | Прямое требование бизнеса. Устраняет зависимость от BI-команды.               |
| **Domain-Driven Design** | Adopt | Выделение bounded contexts и агрегатов | Необходим для правильного разграничения доменов.                              |
| **Anti-Corruption Layer** | Adopt | Защита новой архитектуры от легаси | Критичен для миграции. Позволяет подключать Camel/DWH без изменений.          |
| **CQRS** | Trial | Разделение команд и запросов | Полезен для витрин, но добавляет сложность. Пилотируем на Streaming домене.   |
| **Event Sourcing** | Assess | Хранение состояния как последовательности событий | Сначала изучаем, возможно, применим только для платежей.                      |
| **Saga Pattern** | Trial | Управление распределёнными транзакциями | Нужен для сценария «оплата - лечение». Пилотируем на связке FinTech + Clinic. |

## Инфраструктура и платформа

| Технология | Статус | Назначение | Обоснование статуса                                                           |
|:---|:---|:---|:------------------------------------------------------------------------------|
| **Apache Kafka** | Adopt | Центральная событийная платформа | Индустриальный стандарт. Без неё невозможна EDA.                              |
| **Kafka MirrorMaker 2.0** | Adopt | Репликация событий между доменами | Ключевой компонент для изоляции Medicine Domain.                              |
| **Schema Registry** | Adopt | Управление схемами и совместимостью | Требование первого этапа трансформации.                                       |
| **Kafka Streams** | Trial | Потоковая обработка данных | Нужен для IoT, но требует обучения. Пилотируем на Streaming домене.           |
| **Debezium** | Assess | CDC из легаси DWH в Kafka | В первое время можно обойтись выгрузками. Изучаем для автоматизации миграции. |
| **Kubernetes** | Adopt | Оркестрация микросервисов | Стандарт. Облачные провайдеры предоставляют managed-сервисы.                  |
| **Docker** | Adopt | Контейнеризация приложений для локальной разработки и сборки образов | Стандарт для упаковки приложений, упрощает разработку и CI/CD.                |
| **Terraform** | Adopt | Infrastructure as Code | Критичен для управления облачной инфраструктурой.                             |
| **Prometheus + Grafana** | Adopt | Мониторинг и алертинг | Стандарт. Бесплатно, мощно, большое сообщество.                               |
| **ELK / Loki** | Trial | Централизованное логирование | Логирование нужно, но выбор между ELK и Loki требует пилота.                  |
| **Jaeger / Zipkin** | Assess | Distributed tracing | Полезно для отладки, но не критично на старте. Изучаем.                       |
